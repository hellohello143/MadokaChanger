# Duo LCU state detection

The desktop reads the League Client API through the port and password in the League lockfile. Duo requires HTTPS on that loopback port. Its dedicated HTTP handler accepts the League client's self-signed certificate only when the request URI is loopback.

The phase comes from `GET /lol-gameflow/v1/gameflow-phase`. In `ChampSelect`, the client reads `GET /lol-champ-select/v1/session`, finds the unique `myTeam` entry whose `cellId` equals `localPlayerCellId`, and uses that entry's `championId`. In active game phases it reads `GET /lol-summoner/v1/current-summoner` and `GET /lol-gameflow/v1/session`; it uses `gameData.playerChampionSelections[].championId` only when exactly one selection's `summonerInternalName` matches the current summoner's `internalName`. These local identifiers are discarded after matching and never become duo state. A champion seen in champ select is retained through ready check and the immediate transition into game start and active play if the in-game session cannot identify the local player; other phases and client disconnects clear it.

Riot describes the League Client API as local desktop communication and states that the interface is unsupported and may change without documentation or uptime guarantees: [Riot Developer Portal, League Client API](https://developer.riotgames.com/docs/lol#league-client-api). Riot's separate Game Client API documentation covers the in-game process and its port `2999`; this implementation uses the League client lockfile port instead. Endpoint names and response shapes were cross-checked against the original extracted LCU Swagger served by the [LCU API Swagger index](https://lcu.kebs.dev/swagger), which identified client version 26.16 when checked on October 19, 2026. That schema mirror is community-maintained; a live local Swagger document is authoritative for the installed League client. This checkout was tested with fake LCU responses, without a running League client.

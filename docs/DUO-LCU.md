# Duo LCU state detection

The desktop reads the League Client API through the port and password in the League lockfile. Duo requires HTTPS on that loopback port. Its dedicated HTTP handler accepts the League client's self-signed certificate only when the request URI is loopback.

The phase comes from `GET /lol-gameflow/v1/gameflow-phase`. In `ChampSelect`, the client reads `GET /lol-champ-select/v1/session`, finds the unique `myTeam` entry whose `cellId` equals `localPlayerCellId`, and reports its `championId` only after an action for that cell has `type: "pick"` and `completed: true`. Hovered picks and completed bans do not count. The action proves lock-in, while the current `myTeam` row supplies the champion so accepted swaps and trades are reflected instead of reusing an old action's champion. For autoassigned modes without a completed pick action, the session timer must say `FINALIZATION`; when `benchEnabled` is true, a usable `benchChampionIds` list must also show that the local champion is no longer an available bench candidate. Riot describes ARAM rolls, bench state, rerolls and trades as server-authoritative transactions, which makes the finalized local slot the appropriate source of truth.

In active game phases the client reads `GET /lol-summoner/v1/current-summoner` and `GET /lol-gameflow/v1/session`; it uses `gameData.playerChampionSelections[].championId` only when exactly one selection's `summonerInternalName` matches the current summoner's `internalName`. These local identifiers are discarded after matching and never become duo state. If the just-locked champion select transitions directly into an active game phase and one of those in-game endpoints temporarily returns 404, the verified locked champion is retained for that transition. Authentication, network, malformed-response failures and other phase changes clear it. `ReadyCheck` is before champion select and always clears the previous champion, preventing a dodge or a new queue from inheriting stale state.

Riot describes the League Client API as local desktop communication and states that the interface is unsupported and may change without documentation or uptime guarantees: [Riot Developer Portal, League Client API](https://developer.riotgames.com/docs/lol#league-client-api). Riot's separate Game Client API documentation covers the in-game process and its port `2999`; this implementation uses the League client lockfile port instead. Endpoint names and response fields (`actions`, `actorCellId`, `completed`, `type`, `myTeam`, `timer.phase`, `benchEnabled`, and `benchChampionIds`) were cross-checked against the current [community-maintained LCU Swagger index](https://lcu.kebs.dev/swagger) on October 20, 2026. Riot's [ARAM explanation](https://www.leagueoflegends.com/en-us/news/dev/ask-riot-is-aram-really-random/) confirms that the server tracks rerolls, bench champions and trades transactionally. The local Swagger served by the installed League client remains authoritative. This checkout was tested with realistic fake LCU responses, without a running League client.

# Duo implementation contracts

These contracts connect the relay, desktop transport, LCU detection, temporary overlay state and WPF panel. See [DUO.md](DUO.md) for setup, deployment, architecture and manual verification.

Protocol v1 is camelCase JSON, shaped exactly like Core/DuoProtocol.cs. HTTP operations: POST /v1/rooms body {version:1}; POST /v1/rooms/join body {version:1,code:"0007"}; GET /v1/rooms/{roomId}?generation=...; PUT /v1/rooms/{roomId}/state body DuoPublish; DELETE /v1/rooms/{roomId}?generation=... . Authenticated operations use Authorization: Bearer token. Create/join return DuoMembership; GET/PUT return DuoSnapshot; DELETE returns 204. Error body {error: stable_code, message: friendly text}. Membership tokens stay in memory. No automatic join on process restart.

One SQLite-backed Cloudflare Durable Object coordinates rooms. Secure random four-digit code, collision retry, atomic two-member admission, 256-bit tokens stored hashed, unused invite expiry 10 minutes, room inactivity expiry 2 hours, presence stale after 35 seconds. Snapshot polling every 10 seconds doubles as heartbeat; local state publication only on change, debounce 500ms. The client reconnects using the existing member token, takes a fresh snapshot, and increments its revision beyond its server snapshot. Reject other room/generation, stale room snapshot revisions and stale member publish revisions. Leave clears local membership immediately even on network errors. A canceled create/join response must not install obsolete membership.

State: champion is detected from local LCU, desired is committed Madoka selection only, prepared is the exact selection captured in the active built overlay (can differ from desired), phase is LCU phase, preparation is stopped/preparing/prepared/pending/unavailable/error. LibraryCommit and MetadataPatch identify supported installed catalog; no package transfer, no local credentials or player identifiers. A null desired means no Madoka override; no substitution.

PartyService public API: constructor(IDuoTransport, optional TimeProvider), Membership, Snapshot, IsConnected, Status, event Action Changed, CreateAsync(ct), JoinAsync(code,ct), LeaveAsync(ct), PublishAsync(DuoSelectionState,ct), DisposeAsync(). It owns polling/reconnect, network serialization and validates all incoming snapshots. IDuoTransport is injected; production DuoHttpTransport accepts Uri and optional HttpClient. PartyService must be testable with fast polling through optional constructor interval.

LCU API: ILeagueStateSource.ReadAsync(string? gameFolder, CancellationToken), returns LeagueState(bool Available,string Phase,int? ChampionId,bool IsInGame). Production LcuLeagueStateSource reuses LeagueClientApi credentials and loopback-only TLS handling, verifies endpoint schema sources and adds fake HTTP tests. No port 2999. Poll every 2 seconds from DuoCoordinator only while a room is joined. Unknown/disconnected state clears champion; game process detection remains the authoritative rebuild safety guard as well as LCU active phase.

DuoCoordinator public API for UI: constructor(PartyService, ILeagueStateSource, StateStore, LibraryStore, PatcherController, DuoOverlay), event Action Changed, Party property, LocalState property LeagueState, Status string, Preparation string, Peer property DuoMember?, CreateAsync(ct), JoinAsync(code,ct), LeaveAsync(ct), NotifyCommittedSelectionChanged(), DisposeAsync(). It drives committed state + overlay preparation, never starts a stopped patcher. Receiving peer state never modifies saved selections or republishes peer-owned metadata.

UI owns DuoViewModel with relay URL read from MADOKACHANGER_DUO_URL (default empty, no fictitious public service); accept HTTPS or HTTP loopback only. MainViewModel exposes Duo property and creates panel lifecycle through injected DuoCoordinator. UI can display a configurable relay URL and change transport endpoint only while disconnected (root can supply transport reconfiguration if needed). Prefer environment configuration to expanding saved settings. Root will wire DI. UI worker must notify coordinator after successful Apply/Reset and stop/dispose Duo before patcher shutdown.

Effective overlay = saved selections with exact supported peer champion replacing an unrelated saved preference; local detected champion always wins. Same champion with differing desired overrides (including local default) is a conflict: keep local selection, exclude peer, explain limitation. Missing/ambiguous/incompatible peer package is unavailable, never substitute. Temporary peer state participates in hash and existing file conflict resolution. Backend rebuild must serialize under the same lifecycle mutex as Start/Stop, retain the operation lease throughout rebuild, check game guard before and after build, and respect Stop intent while queued. On leave clear logical peer immediately; physical removal may wait until game exits. A running session rebuilds after stable changes at safe points; stopped sessions only prepare on explicit Start.
